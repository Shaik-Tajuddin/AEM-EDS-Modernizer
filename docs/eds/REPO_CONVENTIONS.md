# EDS Repository Conventions

The repo layout the modernizer produces follows the EDS
conventions: a flat content tree, a `blocks/` folder for
custom blocks, a `scripts/` folder for scripts, a `styles/`
folder for styles, and a `fstab.yaml` for the Franklin
pipeline configuration.

## Layout

```
{eds-repo}/
├── fstab.yaml
├── README.md
├── package.json
├── scripts/
│   ├── scripts.js
│   ├── aem.js                       (generated, optional)
│   └── figma-component-map.json      (Phase 2)
├── styles/
│   ├── styles.css
│   ├── tokens.css
│   ├── themes.css                   (Phase 2)
│   └── figma-tokens.json            (Phase 2)
├── blocks/
│   ├── {name}/
│   │   ├── {name}.js
│   │   └── {name}.css
│   ├── cards/
│   │   ├── cards.js
│   │   └── cards.css
│   ├── hero/
│   │   ├── hero.js
│   │   └── hero.css
│   └── ... (one folder per distinct block)
├── content/
│   ├── us/
│   │   ├── index.md
│   │   ├── about.md
│   │   ├── adventures/
│   │   │   ├── index.md
│   │   │   └── adventures-0.md
│   │   └── ...
│   └── ... (one .md per page)
└── .helix/
    └── (pipeline metadata, not generated by the modernizer)
```

## `fstab.yaml`

```yaml
mountpoints:
  /: https://adobe.sharepoint.com/sites/wknd/eds

folders:
  /: /
```

The modernizer generates the `fstab.yaml` with the
project's configured mount point. For the mock mode the
mount point is `https://eds-mock.local`.

## Paths

- The `AemPageRecord.path` is `/content/wknd/us/en/about`.
- The corresponding EDS path is `us/en/about.md`.
- The path mapping is `aemPathToEdsPath(aemPath)` in
  `UrlRedirectService`:
  - Strip the content root prefix (`/content/wknd`).
  - Replace `/` with `/` (EDS uses forward slashes).
  - Append `.md`.

## `package.json`

```json
{
  "name": "wknd-eds",
  "version": "0.1.0",
  "description": "WKND EDS site, generated by AEM → EDS Modernizer",
  "scripts": {
    "dev": "aem up",
    "test": "aem up --no-open"
  },
  "dependencies": {
    "@adobe/aem-cli": "^1.0.0"
  }
}
```

## `README.md`

The `CodeGenerationAgent` produces a project-specific
`README.md` that includes:

- The project name and description.
- A link to the dashboard job.
- A summary of the changes (page count, block count, AI
  cost).
- A "Local development" section with `npm install && npm
  run dev`.
